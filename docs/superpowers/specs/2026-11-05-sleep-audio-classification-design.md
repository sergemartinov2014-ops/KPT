# Классификация ночных звуков: храп / речь / шорох

Дата: 2026-11-05
Статус: на согласовании

## Зачем

Приложение записывает ночные события, но тип определяется ненадёжно. Сейчас в
`lib/services/sleep_audio_recorder_service.dart` тип выбирается только по
длительности и пиковому уровню:

```dart
if (roundedDuration > 6 && peakDb > -26) type = snore;
else if (roundedDuration > 3 && peakDb > -22) type = talk;
else type = movement;
```

Громкость и длина не различают природу звука: тихий храп попадает в «шорох»,
громкое движение — в «храп», фон комнаты — в «разговор».

## Цель

Классифицировать каждый сохранённый фрагмент по акустическим признакам:
храп, разговор во сне, шорох/движение, фоновый шум.

## Не входит в задачу

- Изменение порога запуска записи и калибровка микрофона: триггер остаётся
  прежним (`startThresholdDb`, `prolongThresholdDb`).
- Переклассификация уже сохранённых клипов: старые записи сохраняют тип.
- Облачные сервисы, ML-модели, новые зависимости.

## Подход

Выбран вариант A: DSP-классификатор на устройстве на чистом Dart, без
сторонних пакетов и сетевых вызовов.

Рассмотренные альтернативы: ML-модель TFLite (потенциально точнее, но +4–16 МБ
в бинарнике, новый плагин, нужен размеченный датасет) и облачное распознавание
(неприемлемо для ночного аудио). Оба отклонены.

## Архитектура

Новый модуль `lib/services/audio_event_classifier.dart`:

- `AudioEventClassifier.classify(Uint8List pcm, {int sampleRate})` →
  `AudioClassification { SleepSoundType type; double confidence; AudioFeatures features; }`.
- Внутри: нарезка на кадры 32 мс с шагом 16 мс, окно Ханна, FFT 512.
- Признаки по кадрам выше адаптивного порога (медиана RMS + 6 дБ):
  - энергия по полосам: 40–160, 160–400, 400–1000, 1000–3000, 3000–6000, 6000–8000 Гц;
  - spectral centroid, flatness, flux;
  - zero-crossing rate;
  - периодicity и F0 по автокорреляции (40–320 Гц);
  - модуляция огибающей 0.25–8 Гц (циклы храпа, слоговая речь);
  - длительность и доля активных кадров.
- Классификация — взвешенные оценки по признакам, выбор максимума.
  Явные правила-предохранители:
  - низкий уровень (< −50 dBFS) → фоновый шум;
  - сильная низкочастотная периодичность + энергия < 400 Гц + низкий flux → храп;
  - энергия 300–3000 Гц + слоговая модуляция + высокий flux → речь;
  - широкополосный шум + высокий flatness/flux + слабая периодичность → шорох;
  - стационарный шум без периодичности → фоновый шум.
- `SleepSoundType.ambient` используется для фона вместо ошибочного «храпа».

## Интеграция

`_finalizeCurrentClip` вызывает классификатор по уже собранному PCM-буферу
(до записи WAV) и сохраняет тип и уверенность.

## Модель данных

`SleepAudioClip` получает необязательное поле `confidence` (0…1, по умолчанию
`null`). JSON читает его совместимо: старые записи без поля загружаются без
ошибок. В карточке клипа показывается уверенность, если она есть.

## Производительность

FFT по кадрам 512 для клипа до 45 с — около 2800 преобразований. Замер на
рабочей машине: ~0,7 с для непрерывного сигнала и ~0,1 с для тишины. Чтобы
финализация клипа не подвешивала интерфейс, `classifyAsync` считает анализ в
отдельном изоляте (`Isolate.run`); UI-изолят не блокируется.

## Проверка

Новый `test/audio_event_classifier_test.dart` с синтетическими сигналами
16 кГц:

- храп: гармоники 80/160/240 Гц с амплитудной модуляцией ~0.8 Гц;
- речь: форманты 700/1200/2600 Гц, F0 ~120 Гц, слоговая модуляция 4 Гц;
- шорох: короткие всплески широкополосного шума;
- фон: стационарный шум низкого уровня.

Тест проверяет ожидаемый тип и уверенность, плюс защиту от старых ошибок:
тихий храп ≠ шорох, громкий шорох ≠ храп.

Существующие 27 тестов должны остаться зелёными.

## Риски

- Пороги подобраны на синтетике; на реальных записях возможны ошибки. Для
  калибровки нужны 10–20 реальных клипов (храп/речь/шорох) с устройства.
- Не меняем триггер записи: очень тихий шорох может вообще не попасть в клип.

## v3 (2026-11-14): реализация и пересмотр решения

Первая версия этой спецификации (выше) выбирала обученную модель на
синтетических данных. Замеры на реальных записях показали, что такой
классификатор не переносится: recall храпа 3.3 % (было измерено на ESC-50,
40 клипов). Причины и полный список изменений — в `docs/SLEEP_AUDIO_DSP.md`.

Итоговое решение v3:

- слой признаков (34) и паритет с `features.py` сохранены;
- слой классификации заменён на прозрачное объединение акустических оценок
  (храп/речь/шорох/фон); обученная модель из runtime удалена;
- детектор события вынесен в `night_sound_detector.dart`: относительный порог
  над локальным шумовым полом, отдельная полоса 60–1200 Гц, пол не обновляется
  во время записи;
- задержка перед началом прослушивания больше не усыпляет приложение,
  добавлены сторожевой таймер и восстановление после прерываний;
- квоты записи подняты и не обрезают ночь;
- минимальная активная часть клипа снижена до 400 мс, чтобы сохранять
  переворачивания в постели;
- утренний экран получил фильтры по типу.

Измерения v3 тем же Dart-кодом: recall храпа 0.95 на целых клипах и 0.867 на
окнах, macro-F1 0.932 на синтетике. Проверка на реальном iPhone в спальне
остаётся обязательной — см. чек-лист в `docs/SLEEP_AUDIO_DSP.md`.
